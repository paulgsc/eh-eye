## What Is This

This repository contains a single markdown file.

That markdown file contains a prompt specification.

That prompt specification exists because modern AI systems are powerful, impressive, capable, and — in daily use — strangely exhausting.

This is not a technical breakthrough.

This is a coping mechanism.

---

## The Situation

The models are objectively better.

They reason more cleanly.
They produce more complete artifacts.
They understand invariants.
They generate entire systems on command.

And yet:

* The latency is worse.
* The UI is heavier.
* The outputs are bloated.
* Everything wants to be a zip file.
* Every answer wants to be a README.
* Every module wants to become a framework.

Somehow the intelligence improved, but the interaction tax increased.

This repository is a small protest against that tax.

---

## The Core Complaint

When you ask for:

> “A module.”

You get:

* A module
* A folder
* A config layer
* A CLI
* A README
* A usage guide
* A roadmap
* A philosophical reflection

You did not ask for a startup.

You asked for a file.

And yet the system assumes:

> “Surely you want a holistic artifact.”

No.
You want something that satisfies invariants.
You want something constrained.
You want something that does not silently expand the problem space.

---

## The README Problem

READMEs are treated as sacred objects.

They are not.

They are lossy compression layers over systems.

They:

* Collapse invariants into prose.
* Replace guarantees with confidence.
* Drift over time.
* Pretend to be documentation but function as narrative.

The underlying system might enforce idempotency.

The README will say:

> “Ensures idempotency.”

Those are not the same thing.

This project exists because documentation inflation is now the default output mode.

---

## The Paradox

Claude (and others) are capable of generating excellent, cohesive source artifacts.

But only after:

1. You define invariants.
2. You constrain scope.
3. You forbid scaffolding.
4. You explicitly ban README generation.
5. You specify no directory trees.
6. You explain that minimality is not a bug.

Once constrained, the system is impressive.

Unconstrained, it is maximalist.

The result is a strange workflow:

* Use one model to reason about invariants.
* Feed constraints into another model.
* Extract the artifact.
* Discard the narrative layer.

This README documents that pattern.

Ironically.

---

## Why This Exists

Because:

* “Helpful” defaults often mean “inflated.”
* Completeness is often confused with correctness.
* UX decisions now shape output structure more than the user’s intent.

The models got sharper.

The product layer got heavier.

So this is an attempt to reassert:

* Minimality
* Explicit invariants
* Constrained sample spaces
* Deterministic artifact generation

No scaffolding.
No pedagogical framing.
No visionary prose.

Just the thing that was asked for.

---

## In Summary

This repository is not anti-AI.

It is anti-unbounded helpfulness.

It is not a manifesto.

It is mild exasperation formalized into a markdown file.

The models are better than ever.

The experience is worse than ever.

So we version-control the constraints.
